# 文件解除占用进程终止安全修复 Implementation Plan

> 使用测试驱动和独立审查执行；用户已确认修复及重新打包，沿用本地 main，不另建分支、不提交或推送既有改动。

**Goal:** 实际终止范围严格匹配确认清单，禁止递归终止子进程并保护桌面资源管理器。

**Architecture:** Windows 层单进程终止保留启动时间身份校验，Core 统一保护系统/桌面进程。App 在确认前复制并按 PID 去重目标，确认及执行期间锁定输入，使用可滚动完整清单展示进程和风险；取消不触发服务。进程终止不承诺不会影响该软件自身的关联行为。

**Tech Stack:** .NET 8、WPF、现有 xUnit；不增加依赖。测试不得结束真实进程或关闭真实文件句柄。

## 1. 底层范围及保护

- [x] 为 Core 的 explorer 等桌面进程保护增加失败测试；修复 FileUnlockSafetyPolicy。
- [x] 为 Windows 进程终止增加可替换 OS 边界的回归测试，验证只传递单进程终止，不递归；保留 PID/启动时间校验、有限等待及错误反馈。
- [x] 仅运行新安全测试与 Core 保护测试；不执行真实进程终止。

## 2. 确认清单与 UI

- [x] App 测试先覆盖确认前快照、按 PID 去重、取消零执行、确认期间禁选禁扫描、执行仅使用确认快照。
- [x] 修改 FileUnlockerViewModel.TerminateSelectedProcessesAsync，接收同步确认回调；在回调前复制只读目标清单并置忙，受保护目标整批拒绝并提示取消勾选。
- [x] 新增 ProcessTerminationDialog（WPF），显示扫描目标、完整可滚动名称/PID/程序路径及数据丢失风险；默认取消，需明确勾选风险后才能确认。
- [x] FileUnlockerView 改名“强制结束所选进程”，接入清单确认；扫描或确认期间禁用路径及浏览，手动改路径清空旧结果防止误认目标。
- [x] WPF 测试确认完整列表、取消默认/风险确认控件及按钮实际绑定，不触发真实进程服务。
