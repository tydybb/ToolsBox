# 全选与压缩包密码找回设计

> 历史记录：用户于 2026-09-18 要求移除压缩包密码找回功能，该功能现已撤下。本文的密码找回方案、测试结果和发布路径仅对应旧版；文件解锁全选功能仍保留。

日期：2026-09-18

项目：宝哥工具箱（Windows x64 / .NET 8 WPF）

状态：用户已确认实施 A（内置引擎）；引擎实测后，用户另确认允许密码/损坏原因不确定时保留提示并继续候选。

## 1. 本次范围

两项独立交付，依次实施：先完成文件占用列表的全选，再新增压缩包密码找回工具。保留现有端口监控、文件解锁、网络流量工具；沿用 main 分支，不创建功能分支。

密码找回针对用户自己或获授权的本地压缩包。通过用户提供的候选密码或组合规则进行离线验证，不声称绕过强加密，也不保证成功。原压缩包、密码和文件内容均不上传。

## 2. 文件占用列表全选

- 在当前“选择”列表头增加复选框，支持全选、取消全选和部分选中状态。部分选中时点击表头变为全选。
- 全选作用于当前扫描结果中的全部占用记录，不仅是可见行；保留逐行选择。显示已选记录数与去重后的进程数。
- 空列表不可全选；扫描或执行解锁操作时禁止修改选择。新扫描结果默认不选中，不继承旧记录的选择。
- 行选择变化应通知界面和表头；集合替换、清空和页面释放时移除旧事件订阅。
- 全选仅修改选择状态，不执行解锁。结束进程仍按 PID 去重，强制关闭句柄仍按记录操作；继续保留原有安全校验和用户确认，并在确认中显示影响数量。

## 3. 压缩包工具入口及格式

左侧新增“压缩包密码找回”，按现有工具的导航、DataTemplate、ViewModel 和 Dispose 生命周期集成。

首版验收格式：

| 容器 | 要验证的加密场景 |
| --- | --- |
| ZIP | ZipCrypto、WinZip AES 加密条目 |
| RAR | RAR3/4、RAR5，包含文件名/文件头加密 |
| 7z | AES 加密，包含文件头加密 |

按文件签名识别容器，不仅依赖后缀。输入路径、浏览选择、拖入单个文件均可；拖入只识别文件，不自动开始密码尝试。

文件解锁和压缩包页面共用已有管理员窗口原生拖放接收入口，按当前页面路由，避免注册第二套相互冲突的窗口钩子。运行任务时不允许拖入替换当前压缩包；目录或多个文件须给出清晰提示。

首版不处理分卷压缩包、自解压 EXE、嵌套压缩包自动递归、损坏修复和其他格式的密码恢复。对不支持的加密方式、缺失分卷、未加密文件或无法确定的格式明确提示，不把它们当作密码错误。

## 4. 内置引擎方案 A

选择内置官方 Windows x64 7-Zip 引擎，由应用控制的无界面辅助进程进行检测及密码验证。用户不用安装 7-Zip。引擎版本固定，不在启动时联网更新。

优先通过原生 SDK/DLL 的密码回调提供候选密码，不将密码放入进程命令行、环境变量或磁盘临时文件。实现前验证该接口能区分错误密码、数据损坏、缺失卷及不支持的方法；若接口能力不足，不静默换成泄露密码的命令行方案。

单文件 EXE 内嵌所需引擎资源；首次使用时释放至应用专用的受控缓存目录，核对固定版本与 SHA-256，从绝对路径加载。不得加载压缩包旁边或 PATH 中同名 DLL；缓存写入及加载必须防止链接重定向或文件替换。

随发布包含适用的 LGPL、BSD、unRAR 许可说明及引擎来源/对应源码链接，满足再分发要求。实际引擎体积及新增的发布体积在打包后实测，不预先承诺大小。

## 5. 密码来源与任务交互

提供两种互斥模式：

1. **候选密码**：多行输入或导入 UTF-8 文本，每行一个密码。仅移除行结束符和文件 BOM，不自动去除密码中的空格，不改大小写；空行默认跳过。候选文件流式读取，不一次载入大文件。
2. **规则组合**：已知前缀、已知后缀，加上未知部分的最小/最大长度和字符集（数字、大小写字母、符号或自定义字符）。未知部分长度允许 0—12；0 表示只验证前后缀组合。按长度递增、字符集顺序生成，不在内存中展开全部组合。

开始前展示模式、候选总量或可计算的搜索规模，并提示大范围搜索可能耗时很长。默认串行验证，一次只运行一个恢复任务；首版不加入 GPU 加速、在线字典下载、后台定时任务或跨重启续跑。

状态至少包括：未选择、就绪、识别中、运行中、停止中、已停止、找到密码、候选已尝试完、失败。提供开始和停止按钮，展示已尝试数量、速度及耗时；总量尚未知时不显示虚假的百分比或剩余时间。

切换工具页面不隐式新建或重启任务，返回时可看到进度。关闭应用会取消恢复任务并回收本工具创建的辅助进程。停止后可重新开始；首版不承诺从停止处续跑。

## 6. 验证正确性、安全与资源边界

- 引擎仅以只读方式访问压缩包，使用测试/丢弃输出模式，不把内部文件写到磁盘，不打开或执行内部文件。
- 密码成功不能仅依据“文件列表可见”或“压缩包打开成功”。需要验证受密码保护的数据及可用的校验信息；无加密内容不能宣称找到密码。
- 单个候选不能完整验证时不返回“密码正确”。7z/RAR 有些密码错误与数据损坏返回相同错误；按用户补充确认，显示“密码可能不符或压缩包损坏”并继续候选，统计并保留该提示直到结束。超时、资源不足、不支持格式仍停止。混合不同密码、文件损坏或不支持的方法不能被包装为全包成功。
- 每个候选有独立的 30 秒默认验证时限；超时停止本次任务并提示无法完成验证，不将该候选当作错误密码跳过。实现提供调整单次验证时限的设置，范围 1—300 秒，以适应大文件。
- 原生引擎运行于独立辅助进程；停止或超时只终止本任务创建的辅助进程，不结束其他软件。使用操作系统进程资源限制，防止异常压缩包无限消耗内存；资源不足明确报错，不误报密码错误。
- 密码只在本地任务内存和受控 IPC 中传递。IPC 验证对端及会话归属；不写入普通日志、异常信息、命令行或自动保存设置。
- 管道使用仅当前用户 SID 可访问的显式 ACL 和中等完整性标签，保留双方 PID/会话验证；不使用同时要求相同提权级别的 `CurrentUserOnly` 开关，否则管理员主进程无法连接低权限辅助进程。管理员调用链以实际 RunAs 测试验收。
- 找到密码后默认遮罩，用户主动点击才显示或复制。不自动写入剪贴板、不自动解压、不清除或修改原包密码。
- 输入损坏或恶意压缩包时主窗口应保持可响应。主程序启动管理员权限的既有要求不变；解析工作进程应使用满足只读访问所需的最低权限，不继承与恢复任务无关的句柄。
- 发布版实测补充：同一 EXE 的 `requireAdministrator` 清单会令低权限工作进程启动返回 Windows 740。清单改为 `asInvoker`，主界面路径在创建窗口前显式 UAC 提权，取消授权即退出；无界面解析分支先分流，仍使用受限令牌。主界面必须管理员授权的用户行为不变。

## 7. 组件边界

- **Core**：候选生成器、输入规则校验、恢复请求/进度/结果模型及服务接口；不依赖 WPF 或原生引擎。
- **Windows**：内置引擎资源校验与加载、原生接口适配、辅助进程及 IPC 生命周期、只读验证、超时/资源限制。
- **App**：新增工具 ViewModel 和页面、导航、拖放路由、开始/停止/结果呈现；不在 UI 线程运行候选枚举或解密。
- **FileUnlocking**：独立实现选择状态通知和表头全选，不与密码恢复耦合。

## 8. 验收

1. 全选、取消全选、部分选中、空集合、新扫描清空选择、滚动后行勾选同步和相同进程多句柄均有测试；不改变原有操作安全限制。
2. ZIP 两类加密、RAR3/4、RAR5、7z 及加密文件头使用已知密码的自建或许可允许再分发的样本验证。每个格式包含错误候选后命中正确密码、全部错误、停止后重启。
3. 增加未加密、损坏、格式误标、缺失卷、空候选、带空格/中文密码、特殊字符、仅前后缀组合、超时、辅助进程退出和应用关闭的测试。
4. 验证文件列表可读但内容加密时不会误报成功；原包内容哈希在测试前后保持不变；磁盘不落地解压内容及明文密码。
5. 从普通资源管理器向管理员主窗口拖入文件，两个相关工具各自正确路由；验证左侧导航选中状态、停止按钮响应及资源清理。
6. 回归既有端口监控、文件解锁和网络流量测试。分别发布不带运行环境及内置 .NET 的单文件 EXE，在实际发布物上验证引擎加载和恢复样例。
