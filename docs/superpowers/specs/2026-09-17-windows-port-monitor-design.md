# Windows 工具箱与端口监控设计

## 目标

创建一个基于 .NET 8 和 WPF 的 Windows 桌面工具箱。首个工具为端口监控器，可持续查看本机 TCP/UDP、IPv4/IPv6 端口及其占用进程，并为后续工具保留清晰的导航和模块边界。

## 首版范围

- 展示协议、地址族、本地地址、本地端口、远程地址、远程端口、TCP 状态、PID、进程名。
- 支持按端口、PID、进程名和地址进行关键字筛选。
- 支持 1、2、5、10 秒刷新频率，默认 2 秒。
- 支持暂停/继续自动刷新和立即刷新。
- 查询在后台运行，不阻塞 WPF 界面。
- 刷新失败时保留上一批结果，并显示错误信息。
- 无法读取进程信息时仍显示网络记录及 PID。
- 首版不提供结束进程、联网、历史持久化或复杂设置。

## 架构

解决方案包含三个项目：

- `ToolsBox.Core`：跨 UI 的领域模型、筛选及刷新协调逻辑。
- `ToolsBox.Windows`：Windows IP Helper API 采集器，封装 TCP/UDP IPv4/IPv6 原生查询和进程名解析。
- `ToolsBox.App`：WPF 主程序、MVVM 状态和工具导航。

`IPortSnapshotProvider` 是核心边界。界面只依赖该接口，不直接依赖 Win32。`PortMonitorViewModel` 通过定时器请求快照，合并筛选结果并在 UI 线程更新集合。

## 界面

主窗口左侧为深色工具导航区，当前包含“端口监控”；右侧顶部提供搜索、刷新频率、暂停/继续和立即刷新，主体使用可排序表格显示连接记录。底部状态条显示记录数量、最近刷新时间和错误信息。

## 错误处理

原生 API 返回错误码时转换为可读异常。进程在采集期间退出或访问受限时使用“进程已退出”或“无法访问”，不使整次刷新失败。自动刷新避免重入；一次采集未完成时不启动下一次采集。

## 验证

单元测试覆盖筛选、排序无关的数据映射和刷新状态；Windows 采集器通过集成测试确认能够返回格式有效的快照。最终执行 `dotnet test` 和 Release 构建。
