# 播放器悬浮下载按钮设计（A 方案）

## 已确认的目标

用户确认采用网页内播放器左上角悬浮按钮：识别实际播放器，优先使用与它对应的已加载媒体资源，点击后由工具箱原生界面确认清晰度和保存位置，最终下载为 MP4。保留现有资源列表、任务队列、普通权限浏览进程和登录目录。

当前阶段：A 方案已实施，验证结果见 `../2026-09-20-player-media-verification.md`。作者署名、证书签名和使用授权是另一个话题，不作为本功能的隐含改动，也不自动申请证书或修改许可证。

## 当前问题及证据边界

- 用户测试链接为 `https://www.douyin.com/jingxuan?modal_id=7680095187900697907`，界面返回“解析视频阶段”的通用失败。
- `PageVideoTargetResolver` 已能把该明确编号转换为视频详情地址；现有 `InspectPage` 仍只把地址交给解析器，不读取播放器与媒体来源之间的关系。
- 固定版本 yt-dlp 的匿名只读元数据探测返回 `Fresh cookies` 提示；这不证明用户没有登录，也不证明视频不存在或受 DRM 保护。当前错误分类把该提示归为普通解析失败，不能据此给出确定性原因。
- 上轮已修复的空名称 Cookie 参数异常与当前站点解析失败不同，不能混为一谈。

## 交互

1. 对可识别的 HTML 视频播放器，在左上角放置小型“↓ 下载视频”按钮，不改播放器原有播放、暂停和音量逻辑。
2. 按钮跟随播放器位置、页面滚动和视频源切换；隐藏、移除或切换到新视频时，作废旧绑定。
3. 区分“已发现播放器”和“已找到下载来源”。没有可靠来源时显示“尚未找到下载来源”，不假装已经能够下载。
4. 点击按钮只选择该播放器并打开工具箱原生确认面板。面板显示可核对的视频标识、来源、可用清晰度和保存目录；用户确认后再解析或加入现有下载队列，不由网页消息直接启动下载。
5. 已有内置/弹出浏览窗口共用同一个 WebView2 实例，两种模式均保留按钮和选中目标。浏览器缩放、播放器调整大小后重新计算位置。
6. 容器全屏时尽量将按钮放在全屏容器内；直接视频元素全屏、无法访问的 iframe 或无法放置按钮的播放器保留原生选择入口，明确兼容限制。

## 识别与资源绑定

- 播放器身份包含文档、frame、元素及媒体源代次；同一个 video 元素被站点复用时，媒体源变化会产生新代次。
- 读取 `currentSrc`、播放状态、可见区域和媒体元数据，配合宿主实际观测到的资源进行绑定；不使用“最后一个视频请求”、相同域名、文件大小或时间接近作为唯一依据。
- HTTP(S) 媒体必须和当前文档中实际捕获的来源精确匹配。若有重定向，只沿实际观测到的重定向关联匹配，不能根据任意网页自报地址发起带凭据请求。
- `blob:`、MediaSource 和 `srcObject` 不是普通下载直链。只有找到可证明属于该播放器的完整资源或播放清单时才启用下载；否则保留明确的单视频页面解析备用入口。
- 多播放器、预加载和多个清晰度来源必须区分；存在歧义时让用户在原生界面选择，不自动下载其他视频。
- 停止持续识别、离开页面、销毁 frame 或关闭窗口时清理观察器、消息关联和悬浮按钮，不保留过期下载目标。

## 权限与消息安全

- 浏览器和媒体引擎继续在普通权限进程内运行，主工具箱权限行为不变。
- 注入脚本仅承担播放器检测和按钮显示，不暴露宿主对象、不读取或向网页回传 Cookie。
- 如果启用 WebView2 消息，协议只允许受限的播放器观察、选择消息。限制类型、大小、数量；核对浏览器提供的文档/frame 来源与宿主登记的候选身份。
- 网页内容和消息始终不可信。随机标识、Shadow DOM、`isTrusted` 不能代替原生用户确认；网页不得指定保存路径、可执行文件、命令参数、任意 URL 或自动读取登录资料。
- 导航或源代次变化后，原生确认面板必须再次检查目标有效性；过期目标拒绝执行。
- 保留网站直接下载拦截、组件安装确认、Cookie 域/路径隔离、敏感日志脱敏和同名文件不覆盖。

## 下载及错误提示

- 优先下载已经验证关联的媒体或清单，复用现有 MP4 封装、合并、必要转码和输出校验；最高质量只指已识别的可用来源，不保证超过网页提供的质量。
- 对存在明确单视频地址的目标保留 yt-dlp 页面解析后备路径；不为下载而绕过 DRM、验证码、付费或账号访问权限。
- 站点接口未取得媒体信息、资源过期、没有可靠绑定、需要用户在网页完成访问、组件缺失分别给出可操作提示，不把未知失败断言为某一个原因。
- 使用用户提供的具体视频链接进行真实页面验收；如果受站点限制无法完成，记录已验证阶段与剩余限制，不把本地样例通过等同于该视频可下载。

## 代码职责

- Core/WebResources：播放器身份、源代次、资源关联和过期目标规则；保持与 WebView2、WPF 无关。
- App/WebResources：固定检测脚本、WebView2 生命周期与受限消息桥接、原生确认面板；大块逻辑使用独立文件，不继续堆入窗口主文件。
- MediaDownloads：复用现有下载/转换服务，补充站点解析失败分类；不在网页桥接层执行媒体命令。
- Tests：纯规则测试、WPF 交互测试和独立 WebView2 本机媒体验收，使用合成凭据，不使用真实账号作为自动化测试数据。

## 验收

- 单个直链播放器按钮定位、选择及真实 MP4 输出。
- 同时两个播放器、预加载下一条、复用元素换源，按钮不下载错误或过期视频。
- SPA 切换、滚动、缩放、独立浏览、frame 移除和全屏边界。
- 无法还原的 blob 显示限制，不冒充 HTTP 下载地址。
- 伪造消息、超长消息、任意路径/URL、重复点击和过期确认均不能自动启动本机下载。
- 原生用户取消不创建任务、不读取下载所需登录信息；确认后才进入现有任务及取消清理流程。
- 安全筛选回归继续排除会实际关闭文件句柄的测试；不结束用户软件、不更改系统权限。
- 交付两份 EXE：不含 .NET 与内置 .NET；README 写明已验证的真实站点结果与未覆盖边界。
