# 宝哥工具箱

面向 Windows 的可扩展桌面工具箱，基于 .NET 8 和 WPF。当前包含实时端口监控、文件解除占用、软件网络流量监控和下班倒计时工具。

## 端口监控

- 读取 TCP、UDP、IPv4、IPv6 端口。
- 显示本地/远程地址与端口、TCP 状态、PID 和进程名。
- 可按端口、PID、进程名、协议、状态或地址搜索。
- 自动刷新频率可选 1、2、5、10 秒，默认 2 秒。
- 支持暂停/继续自动刷新以及立即刷新。
- 刷新失败时保留上一次有效结果。

程序直接调用 Windows IP Helper API，不解析 `netstat` 文本，也不会结束任何进程。普通权限通常足以获取端口和 PID；个别受保护或已退出进程的名称可能显示为“无法访问”或“进程已退出”。

## 文件解除占用

- 可输入完整路径、浏览选择文件/文件夹，或直接拖入单个文件/文件夹。
- 从普通资源管理器拖入管理员窗口时，使用 Windows 原生文件拖放接收路径；仅在“文件解除占用”页面空闲时接收，放下后自动扫描。一次仅接收一个路径，拖入不会自动结束进程或关闭句柄。
- 文件夹检测自动包含其自身以及全部子目录和文件，不需要遍历大目录。
- 文件路径查询在无窗口辅助进程中隔离执行，单个句柄查询超过 250 毫秒会跳过并提示结果可能不完整；扫描最长 30 秒，结束或失败后恢复检测按钮。已以管理员身份启动时，“管理员扫描”直接复用当前权限。
- 显示占用进程、PID、实际占用路径、句柄值、进程路径和权限状态。
- 选择列表头支持全选、取消全选和部分选中状态，覆盖全部当前结果；显示已选记录数及去重后的进程数。扫描或操作时禁用选择，新扫描清空旧选择。
- “强制结束所选进程”会先锁定勾选清单，逐项显示进程名、PID 和程序路径；确认窗口默认取消，必须勾选风险确认才能执行。只终止清单中通过身份校验的单个进程，不递归终止子进程。
- 资源管理器（explorer）、桌面窗口管理器和已知关键系统进程受保护；若选中受保护、缺少身份或身份冲突的记录，会阻止整批操作，提示取消勾选或重新扫描。保护名单不是所有系统进程的完整清单。
- 确认及执行期间不能重新扫描、改变路径或选择；修改路径会清空旧检测结果，避免误操作旧路径的进程。
- “高级危险操作”可以只关闭所选文件句柄，不结束进程。
- 宝哥工具箱启动时会统一请求管理员权限，文件解除占用操作直接使用已获得的系统权限。

> 请优先保存文件并正常关闭相关程序。强制结束进程仍可能丢失未保存数据，且该软件自身的关联窗口或服务可能随它退出；取消进程树终止并不代表零风险。强制关闭句柄也可能使目标程序崩溃、状态异常或损坏数据。ToolsBox 会在终止前复核 PID 和启动时间，关闭句柄前另核验句柄路径，但无法消除这些强制操作本身的风险。

## 网络流量

- 使用 Windows ETW 实时统计 TCP、UDP、IPv4 和 IPv6 的上传、下载流量。
- 默认按可执行文件路径汇总软件流量，可展开查看各个 PID 的实时速度和本次会话累计值。
- 采样只更新原位置的数据，不随瞬时网速重新排列；新软件追加到底部，保留选中行和展开详情。搜索或启用“仅显示有流量”时，列表仍会按筛选条件增减。
- 支持按软件名称、程序路径或 PID 搜索，也可以只显示当前有流量的软件。
- 可为能够读取完整路径的软件设置持久化上传限速，内置 128 KB/s、512 KB/s、1 MB/s 和 5 MB/s，也支持自定义值。
- 限速规则由 Windows QoS 提供，按可执行文件路径保存；软件或电脑重启后仍然生效，可在同一界面解除。

宝哥工具箱启动时会显示 Windows UAC 提示，必须通过管理员授权后才能进入主界面。文件解除占用、ETW 网络监控和上传限速因此可以直接使用所需的系统权限；现有辅助进程仍负责隔离危险操作和网络采集生命周期。关闭工具箱时，网络辅助进程和 ETW 会话会一并退出。

启动入口在创建主窗口前显式申请管理员权限，取消授权则退出；从 EXE 或 `dotnet run` 启动主界面都必须通过管理员权限检查。

> 当前版本只限制上传速度，不限制下载速度。完整的双向限速需要安装网络过滤驱动，已在架构中预留扩展接口，但本版本不安装驱动。系统进程或受保护进程可能无法读取程序路径，此类进程仍会显示流量，但不能设置限速。

## 下班倒计时

- 输入当天上班时间，支持半角冒号 `08:30`、全角冒号 `08：30` 或四位数字 `0830`，也可点击“使用当前时间”填入当前小时和分钟，再点击“开始 / 重新计算”。成功开始后统一显示并保存为 `HH:mm`。所有日期禁止早于 07:30；可以提前填入今天尚未到达的上班时间，页面会标明尚未上班。
- 工作日 / 调休补班日：07:30—09:30（含）上班，正常下班时间为上班时间加 9 小时，已含午休；晚于 09:30 标记“今日迟到”，正常下班仍固定 18:30。
- 工作日加班可为 0（不加班），否则须为整数且至少 2 小时；周末、节假日全天算加班，整数且至少 4 小时。
- 加班扣除实际经过的午休 12:00—13:00、晚饭 19:00—19:30；未跨过的休息不扣除，恰好结束于休息开始时不顺延。支持跨午夜，后续每天仍扣除相同休息窗口。
- 显示正常下班、预计下班、加班内休息扣除、迟到状态和秒级倒计时。倒计时表示真实距离下班的时间，吃饭时仍继续倒数；切换工具不中断，休眠恢复后按系统时间重新计算。
- 到达最终预计下班时间后（包括设置的计划加班），面板显示“你已无偿加班”，大时钟从 `00:00:00` 开始累计超出时间，超过 24 小时不归零。这是对超出计划时间的趣味提示，不判断实际出勤或薪酬。
- 到点弹出一次不抢焦点的置顶提醒，切换其他工具、主窗口最小化仍可提醒；关闭提示不停止计时。每个任务在本次运行只提醒一次，时钟回拨和相同任务重复计算不重复提醒；重置或开始不同任务后重新计，重启恢复当日已到点任务会补提醒一次。退出工具箱后不运行后台提醒。
- 提醒采用蓝底白字的“即将关机”警告样式，正文为“你已经下班，我要把你电脑关了”，保留“关闭”按钮及超时计时，不显示解释性小字。该外观只是趣味提醒，不调用系统关机、注销或进程结束操作，也不锁定屏幕。
- 点击“下班”结束本次计时，关闭已有的到点警告且不再触发后续警告；弹一次结果提示，并在面板保留同样的结果、实际下班时间和已停止的计时数值。工作日早于正常下班时间才提示早退及提前分钟数；正常或超时下班提示“已下班，抓紧回家吧！”。未完成计划加班单独提示，不将其作为早退依据；周末、节假日仅判断计划加班是否完成。
- 未开始计时、尚未到上班时间或已经下班时，“下班”按钮不可用。结束状态与任务一起保存，同一任务日期重开仍保持停止且不补弹结果；保存失败会告警，本次仍保持停止。点击“开始 / 重新计算”可重新计时，“重置”清空结果；无效输入不会破坏已结束状态。
- 有加班时，倒计时卡片额外显示计划加班净时长、带日期的加班起止时间，以及按时长变化的趣味提醒。工作日加班达到 15 小时、周末 / 节假日达到 22 小时时显示超长加班吐槽，仅提醒，不拦截计时；文案不是健康或考勤上限标准。无加班或重置后隐藏，尚未应用的输入不影响当前任务卡片。
- 内置中国大陆 **2026 年**节假日和调休补班日，离线自动识别；来源为[国务院办公厅通知](https://www.beijing.gov.cn/fuwu/bmfw/sy/jrts/202511/t20251104_4258838.html)。允许手动覆盖，公司安排以自行选择为准。其他年份明确提示缺少日历，必须手动选择类型，不会猜测未来调休。
- 修改输入后，需要点击“开始 / 重新计算”应用；修改错误不会覆盖正在计时的任务。跨午夜运行中的任务保持原目标，新开始的任务采用当天日期。
- 本地时间及日期以 Windows 系统设置为准。记录保存在当前用户 `%LOCALAPPDATA%\ToolsBox\work-countdown.json`，只包含任务日期、上班时间、日期类型、计划加班时长及可选的实际下班时间；同一任务日期重开可恢复，旧日期不自动启动。重置会删除记录；保存 / 恢复失败有明确提示，不影响其他工具。

### 下班操作示例

工作日 09:30 上班、计划加班 2 小时：正常下班为 18:30，加班扣除 19:00—19:30 晚饭时间，预计下班为 21:00。

| 点击“下班”的时间 | 面板及弹窗结果 |
| --- | --- |
| 18:00 | 提示早退 30 分钟，另提示计划加班未完成 |
| 18:30 | “已下班，抓紧回家吧！”，另提示计划加班未完成，不算早退 |
| 21:15 | “已下班，抓紧回家吧！”，超出计时停在 00:15:00 |

点击后计时停止，同一任务日期重新打开仍保留结束状态，不再弹出到点提醒。要开始新的计时，请点击“开始 / 重新计算”。

## 环境要求

- Windows 10/11
- 不带运行环境的发布版：安装 [.NET 8 Desktop Runtime（Windows x64）](https://dotnet.microsoft.com/zh-cn/download/dotnet/8.0)。内置 .NET 的版本无需另装运行环境。
- [.NET 8 SDK](https://dotnet.microsoft.com/download/dotnet/8.0)（从源码运行或构建时）

## 运行

```powershell
dotnet run --project .\src\ToolsBox.App\ToolsBox.App.csproj
```

## 构建与测试

### 发布免安装单文件版（不带运行环境）

```powershell
dotnet publish .\src\ToolsBox.App\ToolsBox.App.csproj -c Release -p:PublishProfile=PortableWinX64
```

输出为 `bin\publish\win-x64\宝哥工具箱.exe`，具体体积随内置组件变化。Visual Studio 中也可选择 `PortableWinX64` 发布配置。发布版保留启动时的管理员权限要求。

双击 EXE 后，.NET 原生启动器会先检查兼容的运行环境：

- 环境齐全：直接启动工具箱。
- 缺少 .NET 或所需的 Windows Desktop Runtime：显示官方提示（可能为英文），提供下载入口；用户确认后打开微软下载页面，不自动安装。
- 手动下载入口：[.NET 8 官方下载页](https://dotnet.microsoft.com/zh-cn/download/dotnet/8.0)，选择 **.NET Desktop Runtime → Windows → x64**，安装完成后重新运行工具箱。运行发布版不需要安装 SDK。

该检查发生在 WPF/C# 代码执行前，不需要另加托管检测窗口。行为参考：[微软启动器说明](https://devblogs.microsoft.com/dotnet/dotnet-apphost-improvements/)。若电脑人为设置了 `DOTNET_DISABLE_GUI_ERRORS=1`，官方弹窗会被禁用；正常发布配置不会设置该变量。单文件依赖中的原生 DLL 会按 .NET 机制释放到用户临时目录，并非运行时完全不落盘。

### 发布免安装单文件版（内置 .NET）

```powershell
$publishOutput = Join-Path (Get-Location).Path 'bin\publish\self-contained-win-x64'
dotnet publish .\src\ToolsBox.App\ToolsBox.App.csproj -c Release -p:PublishProfile=PortableWinX64 -p:SelfContained=true -p:EnableCompressionInSingleFile=true "-p:PublishDir=$publishOutput"
```

请在仓库根目录运行上述命令，输出为 `bin\publish\self-contained-win-x64\宝哥工具箱.exe`。发布产物位于 Git 忽略的 `bin` 目录，不随源码提交。

### 自动化检查

日常回归使用以下安全筛选命令，排除会实际关闭辅助进程文件句柄的测试：

```powershell
dotnet test .\ToolsBox.slnx --configuration Release --filter 'FullyQualifiedName!=ToolsBox.App.Tests.Startup.SystemHandleScannerTests.CloseHandleAsync_ReleasesChildProcessFileHandleWithoutEndingProcess'
dotnet build .\ToolsBox.slnx --configuration Release --no-restore
```

被排除的 `CloseHandleAsync_ReleasesChildProcessFileHandleWithoutEndingProcess` 仅应在确认风险后的隔离测试环境中单独运行；不要将不带筛选的全量测试作为日常检查。自动化通过不代表已验证最终 EXE 的 UAC、真实弹窗、最小化提醒及休眠恢复。

网络辅助进程的实际运行验证需单独执行（Windows，可能显示 UAC 提示）：

```powershell
dotnet run --project .\tests\ToolsBox.NetworkSmoke --configuration Release -- "E:\work\ToolsBox\src\ToolsBox.App\bin\Release\net8.0-windows\宝哥工具箱.exe"
```

请将最后的路径替换为实际构建的程序路径。该验证检查辅助进程不打开主窗口、两轮 ETW 回环 UDP 流量采集与停止重启、读取 QoS 规则以及正常退出；不会新增或修改限速规则。

可在管理员 PowerShell 中验证发布版的缺失环境错误路径：

```powershell
.\scripts\Test-MissingRuntime.ps1 -ExecutablePath .\bin\publish\win-x64\宝哥工具箱.exe
```

脚本只为测试子进程指定隔离的运行时目录，不卸载现有 .NET，不修改全局环境变量。为避免自动化被对话框阻塞，仅在测试子进程中禁用 GUI 提示并检查错误码、缺失框架名称和官方下载链接；这不代替干净 Windows 机器上的弹窗与下载按钮人工验收。

## 项目结构

- `src/ToolsBox.Core`：端口模型与刷新协调、文件操作安全规则、下班时间计算与节假日日历。
- `src/ToolsBox.Windows`：Windows IP Helper API、系统句柄扫描、ETW 网络采集、提权 IPC 和 QoS 管理实现。
- `src/ToolsBox.App`：WPF 工具箱外壳及四项工具界面、下班提醒与本地计时状态保存。
- `tests`：领域规则、进程操作安全、状态恢复、WPF 控件集成测试及独立网络冒烟验证。

新增工具时应保留独立的领域/平台边界，并在 `ToolsBox.App` 中增加对应导航和视图。
